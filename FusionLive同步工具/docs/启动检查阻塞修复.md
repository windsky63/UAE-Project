# 启动检查阻塞修复

服务器2026年10月30日的线程堆栈显示，调度在登录前检查中，经openpyxl导入NumPy原生模块时一直等待。此时正式同步进程尚未启动，因此没有当天run.log；安全停止也无法中断原线程中的依赖加载。

本更新将检查放在独立进程主线程执行。检查日志包含当前阶段，每10秒提示等待状态，最长等待120秒；超时或收到停止请求后结束离线检查子进程，不启动平台登录。依赖仍然无法加载时，日志会明确指出最后一个检查阶段。下载仍保留原定时窗口和范围确认要求。

1. 已卡住的旧调度需要结束后再更新。管理中心的安全停止请求已发出；若仍无法退出，在任务管理器核对并结束本项目原卡住的调度Python进程。2026-10-30 05:12诊断中，持有scheduler.lock的PID为69684；PID可能变化，结束前核对当前进程所属项目。
2. 将完整更新包解压并合并覆盖FusionLive同步工具目录。保留runtime、downloads、history、logs、exports及服务器自定义配置，不删除台账或解析缓存。
3. 在项目根目录CMD中运行离线检查：

```cmd
.\.venv-analysis\Scripts\python.exe -X utf8 .\FusionLive同步工具\main.py preflight
```

4. 检查通过后，在管理中心重新启动平台同步。窗口内（北京时间02:00—10:30）会按原流程继续；窗口外等待下一次同步。
