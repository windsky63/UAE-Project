# 误归档旧副本修复方法

版本：2026.11.04-predecessor-identity.1。

适用情况：最新版尚未下载，真实旧副本却被归档到 history，导致有效文件数下降。修复后，同一资料包中的不同文件不能相互充当旧版占位；疑似相关但不能确认同一成员的文件仍保守保护。

## 在服务器执行

1. 在管理中心安全停止 FusionLive 同步、后台解析及 NAS 上传，等待当前任务退出。
2. 将修复 ZIP 解压到服务器项目根目录，覆盖同名程序文件。包内只有程序、发布校验清单和本文，不含台账、下载文件、历史文件、账号或凭证。
3. 在项目根目录打开 PowerShell，先运行程序完整性检查。输出应为同一修复版本，且程序哈希检查通过；如有其他文件版本不匹配，先补齐完整更新，避免混用程序。

```powershell
& '.\.venv-analysis\Scripts\python.exe' '.\FusionLive同步工具\main.py' preflight --startup
```

4. 生成恢复预览。这个命令只读台账、校验候选旧副本的大小和 SHA-256，不移动文件、不改写原台账；结果写入 `FusionLive同步工具/runtime/path_maintenance_preview.json`。

```powershell
& '.\.venv-analysis\Scripts\python.exe' '.\FusionLive同步工具\main.py' path_maintenance --restore-only
```

查看预览的 `restored` 数量、`moves` 清单和 `warnings`。只恢复当前仍未下载、能明确对应同一文件且实际历史副本存在的条目；其他文件不作为占位。需要读取并校验大量历史文件时，预览可能耗时数分钟。

5. 执行恢复，并离线更新今日统计：

```powershell
& '.\.venv-analysis\Scripts\python.exe' '.\FusionLive同步工具\main.py' path_maintenance --restore-only --apply --refresh-report
```

执行前自动使用 SQLite 备份接口保存台账到 `FusionLive同步工具/runtime/backups/before-unified-paths-*.sqlite3`。迁移逐项持久记录并在发布前校验 SHA-256；中断保留恢复记录。目标已有文件或候选损坏时停止，保留原件，不覆盖。

恢复将同一文件的一份可用旧副本从 history 移回正常下载目标，并更新其历史路径。该当前文件仍为 pending/failed 等未完成状态，旧副本不会冒充最新版已下载。此模式不归档其他下载文件，也不整理其他历史文件；重复执行不会重复恢复已经有正常旧副本的条目。

`--refresh-report` 只重建服务器当天 `FusionLive同步工具/logs/日期/推送状态.json` 和 `微信推送文.txt`，不调用微信发送。下次正常调度仍按原有发送设置工作。管理中心刷新后，下载目录统计读取新的状态；主卡“累计已下载版本”仍按版本统计，应通过推送状态中的 `effective_downloads.total.files` 核对有效文件数。

6. 再运行一次预览，检查已恢复条目不再列入；核对有效文件数、旧版占位数及警告，再恢复正常同步和上传。

## 预期与边界

提供的服务器台账包含 1,801 个可疑归档的当前待下载文件。这是候选排查规模，不能保证能恢复 1,801 个实体：实际恢复数取决于服务器 history 中的文件是否存在、SHA-256 是否正确、目标是否无冲突。不会为了凑回昨日数字而虚增计数。

业主清单本身从 15,290 减少到 15,269，范围变化应单独核对。恢复统计按当前有效内容 ID 去重，同一文件新旧版不重复相加。

不能在只有根目录导出台账的开发机执行真实恢复。应使用服务器原始 `FusionLive同步工具/runtime/ledger.sqlite3`、downloads、history，不能把导出的根目录 ledger.sqlite3 覆盖回服务器。

若存在未完成迁移，`--restore-only` 会拒绝开始。先用普通整理入口恢复已有记录；尚未移动的旧版错误归档计划会先备份、撤销，再按新版规则规划。若提示“旧版归档计划已部分移动文件”，保留 runtime/path_migration、layout.pending 和台账备份，不要删除标记或强行继续，需按暂存现场核对恢复。当前提供的服务器台账中 layout_moves 均为 done，没有这种未完成迁移。

恢复后的日志与清单：`runtime/path_maintenance_applied.json`、`runtime/path_migration.log`（以实际迁移进度输出路径为准）、`runtime/backups`。发生冲突时按提示定位原文件和历史副本，保留现场。
