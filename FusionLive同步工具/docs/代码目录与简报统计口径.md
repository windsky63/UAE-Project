# 代码目录与简报统计口径

## 代码整理

原来为逐项测试和修复不断新增了小模块，但未及时归类。本版合并职责紧密相关的代码，并将程序实现收纳到 `app/`，根目录只保留一个 Python 入口 `main.py`，原有 CMD 名称不变。

| 原模块 | 整理后 |
|---|---|
| `local_analysis.py`、`archive_reader.py`、`pcf_input.py` | `app/local_analysis.py`，负责解压、PCF输入规范化及文件分析汇总 |
| `daily_log.py`、`report_stats.py`、`push_report.py` | `app/reporting.py`，负责日报、统计及日志输出 |
| `business_type.py`、`unit_reference.py` | `app/business_type.py`，共用编码规则与单元名称表 |
| 其余根目录Python程序 | 移入 `app/`，保留其独立职责 |

PCF/IDF几何解析器、平台网络访问、后台队列、微信界面操作仍保留独立模块：它们的运行和测试边界不同，全部合成一个文件会增加维护与排错难度。

数据库、下载文件和日志仍使用根目录下的 `runtime/`、`downloads/`、`logs/`，配置JSON位置不变。模板兼容原 `templates/管道简报模板.xlsx`，也支持 `data/管道简报模板.xlsx`。`wechat_push/` 已是独立功能包，保持原位置。

本版在目录整理基础上调整统计口径，区分文件数量与解析指标。使用新的解析版本重新排队，不将旧解析结果回填为新统计。

迁移采用干净程序目录，保留原runtime、downloads、logs及自定义配置，不需要额外清理脚本。

命令行改用统一入口，例如：

```text
python main.py preflight --gui --wechat
python main.py scheduler
python main.py briefing
python main.py analysis_worker --watch --resume
python main.py business_type --filename 文件名
```

## 简报的单元与名称

Excel首个工作表“简报”按厂区汇总：`H1-001`、`H1-002`统一计入`H1`，`H4-262`计入`H4`。主表显示厂区编码，不用单元名称代替厂区名称。无法识别归属的单元和跨单元文件保留独立分类，不猜测厂区。不同项目分别汇总。

第二张工作表固定为“单元汇总”，所有单元在同一张表中按文件数量、已解析管线数量、PCF焊接量三个部分展示，不再逐单元建表。单项目时前三列为单元号、英文名称、中文名称；多项目时首列增加项目以区分同名单元。图片只渲染厂区汇总主表“简报”。其余统计依据、文件明细、焊口明细等工作表保留。

厂区文件数累加所属单元的已发现文件数；管线和焊接指标只累加各单元已知的有效解析结果，作为有效小计。部分单元缺失不清空其他单元的有效值；某项指标完全未知时才显示“—”，不将未知值当作0。每部分独立隐藏所有指标均未知的行，合计行也遵循此规则；数值0是有效值，保留显示。

单线图目录根据台账文档编号识别单元；PCF/IDF优先从解析出的管线号识别，再参考源文件、压缩包和包内路径。不能唯一判断时列为“未识别单元”。保留厂区前缀，避免不同厂区的同号单元混淆。

名称读取根目录 `document_coding_rules.json`，与统一编码规则Excel一致。英文来自编号规定附表，中文为译名；同号多义、原文要求另行确定的名称显示待核对。候选名称及页码记录在Excel“单元名称依据”工作表。

## 每群发布设置

启动设置保留全局“推送文”“简报图片”开关，并在每个接收会话旁提供独立的“推送文”“简报”选项，可仅发文字、仅发简报、两者都发或都不发。全局开关与会话开关同时开启才发送对应内容；会话左侧勾选控制是否参与定时发布。选择保存在 `runtime/wechat_push.json` 的 `recipient_publications` 中。

旧配置没有会话级选项时，沿用原有全局开关行为。关闭所有会话的简报后，文字定时发送无需有效图片；关闭发布仍照常生成文件。手动测试仍向指定测试对象发送文字和图片，不受定时会话选项控制。

## 当前可见统计量

### 主表第一部分：文件数量

| 统计量 | 当前取值和计算方式 |
|---|---|
| PCF文件数、IDF文件数 | 各自按当前有效内容对应的已下载文件路径和已展开包内文件路径计数，解析失败也保留文件计数。一文件多管线仍计1个文件；不同路径的相同内容仍是不同文件。 |
| 单线图PDF文件数 | 只统计文件自身编号按已确认规则识别为管道专业单线图的PDF。电气单线图及其他已确认文档不计入；无法确认的PDF单列待分类。13-61不直接认定为单张单线图，也不以目录名或台账ISO标签推断附件性质。PDF文件数不是页数、张数或管线数。 |
| SHA文件数 | 按.sha扩展名登记文件；即使尚无内容解析器也可计数。 |

未下载、未展开、损坏或受大小限制而未展开的压缩包不估算内部数量。主表注明“已发现文件”，0只表示当前已发现清单中没有该类型，不表示所有压缩包检查后确认为0。未接入文件清单时显示“—”。

同一压缩包同路径同内容条目按解压去重结果计1个文件；同路径异内容按保留后的两个独立路径计2个。重复内容的压缩包仍逐包登记文件，管线解析继续去重。多管线文件若涉及多个单元，文件本身列入“跨单元文件”一次，管线按各自单元统计。

### 主表第二部分：解析后的管线数量

PCF、IDF分别按项目、单元、来源格式、管线标识去重，标识不区分大小写。一文件可贡献多条管线，多文件含同一管线且内容相同只计一条。同管线不同内容记录冲突并排除该管线的管线数及焊接量；同组其他有效管线继续汇总。没有任何有效管线时保持未知，不用0冒充已确认无管线。

单线图PDF和SHA管线数保留“—”，内容解析后续接入；不以PDF/SHA文件数量代替。补充模板可导入有明确依据的已解析管线统计。

### 主表第三部分：PCF焊接设计量

| 统计量 | 计算方式 |
|---|---|
| 焊缝数 | 逐管线根据元件连接拓扑识别焊口，生成焊口表后计行数；保留原PCF解析器的关联材料筛选，排除标记不进入焊口表的记录和螺纹连接 `scw`。不是直接数PCF文本中的WELD行。 |
| 寸口量 | 对每个纳入统计的焊口，将公称直径DN按解析器标准表换算成NPS英寸，再累加NPS。不是周长，也不是直接将DN除以25.4。例：10个NPS 2英寸焊口合计20寸口。 |
| 预制焊缝数 | 在同一批有效焊口中，归为预制的焊口条数。 |
| 预制寸口量 | 上述预制焊口的NPS英寸之和。 |
| 安装焊缝数 | 在同一批有效焊口中，归为现场安装的焊口条数。 |
| 安装寸口量 | 上述安装焊口的NPS英寸之和。 |

默认分类模式 `none`：使用文件明确的SHOP/FIELD等标记，不把未知焊口强行归类。预制和安装分别显示已明确分类的小计，未分类焊口不清空已有分类数据。如果某分类没有已识别焊口且仍存在未分类焊口，该分类保持未知；全组均已分类且该分类确实无焊口时才显示0。寸口量仅累加已知口径，所有口径未知时保持空；分类和口径覆盖情况记录在“焊口分类核对”表，不能把有效小计当作完整设计总量。

PCF逐个WELD块优先读取`WELD-ATTRIBUTE3`，无法识别时回退到原有`WELD-LOCATION`。忽略大小写、前后空白及独立的`weld`单词：`shop`、`frefab`、`prefab`、`pre-fab`归为预制；`field`、`site`、`install`归为安装。其他值保持未知，不按相邻管件的FABRICATION-ITEM推断焊口分类。

可选估算模式需显式指定：`no-small` 将DN＜50及olet/seton归安装，其余归预制；`all` 不使用小口径条件，但仍将olet/seton归安装。文件明确标记优先于估算。结果会注明“含规则估算”，不能作为实际施工完成量。

### 其他工作表

差值移到“管线差值”工作表，计算单线图管线数−PCF管线数、单线图管线数−SHA管线数，两侧已知才计算。主表及生成的图片不含差值。IDF焊接解析指标保留在“统计依据”和焊口明细中，不混入PCF焊接量。原“图纸数”兼容补充模板字段保留在审计表，不作为新版主表指标。

“文件数量明细”保存每个文件的路径、类型、规则依据及处理状态；“压缩包文件明细”保存原条目与实际保存路径。“简报”是唯一转图片的工作表。

新版`runtime/file_analysis/queue.sqlite3`增加`file_inventory`和`pipeline_inventory`表；`current_file_inventory`、`current_pipeline_inventory`视图只选有效任务，历史任务留存但不参与当前统计。管线明细是按源任务保存的审计记录，跨任务可能重复，查询管线总数仍须按项目/单元/来源/管线标识去重并处理冲突，不能直接数行。

## 汇总和完整性

- 文件数量为已发现清单小计；管线数、PCF焊接量的单元、厂区和合计逐指标仅累加有效值，未知不计入；完全未知的指标显示“—”，全未知行不显示。差值仍要求两侧均有已知值，不把未知当0。
- 同一项目/单元/来源内的解析失败或版本/分段冲突不再清空整组，保留成功且无冲突管线的小计。不完整范围仍保存在统计依据和生成状态中，不能把有效小计解释为完整总量。
- `2026.10.27-valid-subtotals.1`仅调整汇总和显示，兼容其前一版缓存。新增WELD-ATTRIBUTE3识别的版本会更新解析缓存键，后台启动后自动重新排队处理本地文件，避免继续采用旧的未分类结果；历史记录保留。
- 本地台账候选缺失或大小不符时，已有结果只代表本地可分析范围，标记为局部结果。
- 简报读取后台已提交的分析缓存，不等所有任务结束才生成。队列任务的done数量不等于管线数、图纸数或焊缝数。
- 所有焊接量为文件推导的设计量，不代表已预制、已安装或已完成焊接的施工实绩。
- 源文件、包内条目、焊口和统计依据保存在相应审计工作表中；微信只发送日报原文和简报图片，不追加处理进度。
