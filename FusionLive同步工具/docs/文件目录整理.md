# 文件目录整理

根目录统一使用 **整理文件目录.cmd**，选择 `1` 预览，选择 `2` 执行。
输入选项后按回车。入口使用上级项目目录的 `.venv-analysis/Scripts/python.exe`，不依赖系统PATH中的Python。
启动失败或整理报错时保留窗口，日志见 `runtime/path_maintenance_launcher.log`；实际整理进度见 `runtime/path_migration.log`。
更新时同时替换CMD、`app/path_maintenance_launcher.py` 和发布清单，不能只复制CMD。
旧的路径迁移和历史修复命令已合并到同一流程，不需要按顺序运行多个工具。

## 在服务器执行

1. 安全退出同步、调度、后台解析及正在进行的推送，关闭文件台账窗口。
2. 将更新程序文件合并到服务器原安装目录。保留服务器原来的 `runtime`、`downloads`、`history`、`logs` 和配置，不用将这些数据复制到开发电脑。
3. 双击 `整理文件目录.cmd`，先选择 `1`，查看 `runtime/path_maintenance_preview.json`。
4. 选择 `2` 执行。工具自动备份台账，校验文件大小和 SHA256，保存中断恢复记录后移动文件。
5. 完成后恢复正常启动。若整理被中断，再运行同一个工具并选择 `2` 继续。

服务器旧版留下的四个快捷入口可删除：`迁移已有文件.cmd`、`预览路径迁移.cmd`、`修复历史目录.cmd`、`预览历史目录修复.cmd`。旧命令 `python main.py file_layout` 和 `python main.py history_repair` 保留兼容，均进入统一工具。

命令行默认只预览：

```powershell
python main.py path_maintenance
python main.py path_maintenance --apply
```

程序和数据不在同一目录时，指定包含 `runtime/ledger.sqlite3`、`downloads` 和 `history` 的安装根目录：

```powershell
python main.py path_maintenance --base-dir "D:\同步工具"
python main.py path_maintenance --base-dir "D:\同步工具" --apply
```

## 整理内容

- 整理当前下载文件的平台目录、文件名及超长路径，更新台账和解析队列引用。
- 将 `history/version-*`、`history/inactive-*`、`history/untracked-*` 批次目录合并到对应的平台历史目录。同名版本分别保留，不按内容删除历史文件。
- 对最新版本尚未下载的文件，从历史记录中选择最近可用且有 SHA256 的旧版本，恢复到对应的下载位置。其余更早版本留在历史目录。文件 ID 变化时结合文档版本关系匹配。
- 恢复的内容仍是历史版本：最新文件保持待下载/失败/受限等原状态，不填写最新版本的成功路径、哈希或下载时间。旧版本仅更新自身的历史路径，直到新版本下载成功后再归档。
- 下载目录已经有可用旧版本时，不再恢复另一份。最新版本已经下载时，只整理历史目录，不用旧版本替换它。

目标占用、台账与文件内容不一致、目录映射不明确时保留现场并提示核对；缺失文件不会假装恢复成功。只有台账却没有实际下载/历史数据的目录，禁止执行整理。所有操作均在本地，不登录业主平台、不重新下载、不连接 NAS、不发送微信。

## 备份和恢复

- 统一执行前备份：`runtime/backups/before-unified-paths-*.sqlite3`。
- 执行方案：`runtime/path_maintenance_applied.json`。
- 文件移动日志：台账中的 `layout_moves`。发生中断时，先恢复旧日志，再重新计算剩余整理方案；也能接续旧版 `history_repairs` 日志。
- 目录整理完成后只清理空目录；不会删除历史文件内容。恢复到 downloads 的旧文件也不会被正常下载前的目录整理提前归档。
