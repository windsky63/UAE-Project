# 历史目录修复

**当前入口已统一为根目录的 `整理文件目录.cmd`。请按[文件目录整理](文件目录整理.md)执行，支持整理历史目录并恢复新版未下载的旧文件。以下保留旧版单独修复工具说明，当前以统一工具为准；旧命令也会转入统一流程。**

适用于已经执行原目录迁移、history下出现version-*、inactive-*、untracked-*批次目录的安装。

先等待原目录迁移完成，再停止下载、调度和后台解析任务。将更新包中的FusionLive同步工具目录合并覆盖服务器同名目录，保留数据库、history、downloads及配置。上传工具目录的更新用于同步识别修复后的历史目录。

双击“预览历史目录修复.cmd”检查计划，预览文件为runtime/history_repair_preview.json；双击“修复历史目录.cmd”执行。也可运行：

```powershell
python main.py history_repair
python main.py history_repair --apply
```

修复示例：

```text
history/version-100/HABSHANDBN/608200/目录/图纸__rev_A__id.pdf
history/version-200/HABSHANDBN/608200/目录/图纸__rev_B__id.pdf
↓
history/HABSHANDBN/608200/目录/图纸__rev_A__id.pdf
history/HABSHANDBN/608200/目录/图纸__rev_B__id.pdf
```

不同版本放在同一平台目录，保留原有身份后缀。文件名相同时追加原批次标识区分，保留每一份文件，不按内容去重。Windows路径超长时使用history/long_path保留接续目录，同一平台目录按最长文件名统一计算缩短位置。完整目录映射保存在台账的history_paths中，NAS上传会恢复全部平台父级，且不再创建版本批次目录。

执行前自动备份台账；逐个校验SHA256并持久化修复进度。中断后再次执行同一修复命令继续。完成后更新file_history及已失效文件的路径，并删除history下空的旧目录。未登记的历史文件同样保留。无法确定原目录、内容冲突或原迁移未完成时停止并保留文件。

此命令不移动、改名或清理downloads，不更改当前有效文件记录，不重新下载，不连接NAS。NAS目录调整由更新后的上传工具在后续上传时校验并迁移。

原“迁移已有文件.cmd”仍是当前与历史文件的整体整理入口；修复历史目录请使用本次新增的专用命令。
