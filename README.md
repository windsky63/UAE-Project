# 阿联酋项目工具集

面向项目资料的下载、解析、备份、知识库同步和微信问答工具集。日常操作建议从管理中心进入；各业务工具仍保留独立运行入口。ima 的可视化操作统一在管理中心内提供。

## 工具一览

| 工具 | 用途 | 常用入口与说明 |
| --- | --- | --- |
| 管理中心 | 统一查看运行状态、配置、文件资料、每日推送和日志；启动、安全停止各工具；提供网页 Codex 对话 | 根目录 `打开管理中心.cmd`；[详细说明](管理中心/README.md) |
| FusionLive 同步工具 | 从平台盘点和增量下载文件，维护下载台账与历史版本；后台解析 PCF/IDF 等资料，生成管道简报、Excel 和微信推送文 | 管理中心“同步工具”；独立入口 `FusionLive同步工具/启动正式下载.cmd`；[使用说明](FusionLive同步工具/docs/使用说明.txt)、[解析说明](FusionLive同步工具/docs/后台解析与预制分类.md) |
| 绿联云上传工具 | 根据同步台账将已校验文件上传至 NAS，支持续传、SHA-256 核验、历史归档和目录镜像 | 管理中心“上传工具”；独立入口 `绿联云上传工具/启动每日上传.cmd`；[使用说明](绿联云上传工具/使用说明.txt) |
| ima 知识库管理 | 只读提取本地项目管理规定和 PDF 图纸副本，预览上传计划，同步到 ima，维护回执、旧版归档与每日更新记录 | 管理中心“ima 知识库”；[详细说明](Ima知识库管理/README.md) |
| codex-wechat | 监听已配置的微信群或私聊，将问题交给本机 Codex，按授权读取项目资料并通过微信回复；维护消息队列、去重和会话记忆 | 管理中心“微信与 Codex”；[安装与使用](codex-wechat/README.md) |

资料流向：FusionLive → 本地下载文件与台账 → NAS 镜像 / ima 资料副本。管理中心汇总状态，微信与网页 Codex 使用配置中授权的项目资料。

## 安装与启动

1. 在 Windows 安装 Python 3.12（包含 pip、venv 和 Tcl/Tk），双击根目录 `install_python312.cmd`。它通过 `setup_python312.py` 创建或补齐共享 `.venv-analysis`，按根目录 `requirements.txt` 安装依赖；已有非 3.12 环境时会停止并提示处理。
2. 按下方“本地配置”设置路径、账号与目标。使用 Codex 功能还需安装并登录本机 Codex CLI；微信自动发送需要已登录的桌面微信和可交互的 Windows 桌面。
3. 双击 `打开管理中心.cmd`，默认使用 `127.0.0.1:8765` 并自动打开浏览器。打开或刷新页面不会自动启动下载、NAS 上传或微信发送。
4. 先在各工具页面检查配置和状态，再启动所需工具。“一键启动所有工具”会使用已保存的配置执行各工具任务。
5. 停机时使用页面的“安全停止”或“一键安全关闭所有工具”，等待任务收尾。关闭浏览器或管理中心窗口不能替代业务工具的安全停止。

局域网访问使用 `打开管理中心-局域网.cmd`；切换前先关闭已有管理中心服务。其他电脑访问 `http://服务器IP:8765/`，实际文件读写和工具运行均发生在服务器。该模式无需登录或会话链接，应仅向可信网络开放；配置与防火墙说明见[管理中心 README](管理中心/README.md)。

## 各工具常用操作

### FusionLive 同步

- 下载、后台解析和简报发布由各自的任务状态管理。正式启动会沿用保存的下载范围、账号和发布设置；运行时间以当前配置及[使用说明](FusionLive同步工具/docs/使用说明.txt)为准。
- `打开文件台账.cmd`：查看本地目录、文件及进度。
- `生成管道简报.cmd`：读取本地解析缓存生成 Excel 和图片，不登录平台、不下载。
- `安全退出.cmd`：保存进度并等待同步、解析及已开始的推送收尾；较大文件可能需要等待。不要用强杀进程代替。
- 管理中心“每日推送”可查看每日文件及投递明细。手动推送使用当天已就绪文件和已保存接收方，确认后才发送。

### NAS 上传

先配置源文件目录、FusionLive 下载台账和 NAS 目标路径，再从管理中心启动，或使用 `启动每日上传.cmd`。`检查程序完整性.cmd` 用于本地完整性检查；`检查连接与清单.cmd` 会检查实际连接及清单；`配置NAS本机校验.cmd` 用于配置 NAS 端校验。

NAS 目标根目录应作为本工具的专用镜像目录。完整轮次校验后，多余文件和旧目录会移入目标旁的 `目标目录名.nas-archive`；不要在镜像目录存放需要独立保留的人工资料。范围内文件缺失、映射不明或校验失败时会暂停，原因见该轮日志和汇总报告。

### ima 知识库

在管理中心按“配置凭证和目标 → 提取本地资料 → 扫描本地文件 → 预览上传计划 → 手动同步”操作。资料提取读取同步工具数据库和下载原件，只复制符合规则的资料，保留原件。预览上传计划会连接 ima 检查云端情况，但不上传。

自动同步使用已保存的开关和北京时间计划，默认每日 13:00；手动与自动共用一天最多一次的同步记录。入库成功表示接口已接受，解析可能仍未完成。结果不确定时先核对回执，不通过删除状态库重试。待同步根目录的 `每日更新记录.txt` 保留逐文件更新记录。

### 微信与 Codex

先配置数据库账号、允许监听的会话及可访问目录，完成环境检查后启动监听。群聊触发和回复方式按会话配置执行。网页与微信可复用本机 Codex 后端，分别维护对话记录与权限。

在 `codex-wechat` 目录执行 `..\.venv-analysis\Scripts\python.exe -m wechat_local --check` 可检查环境；`--once` 仍可能按配置调用模型并发送，不应作为只读检查使用。

微信实际发送期间会占用桌面并保护键鼠输入。紧急恢复使用 **Ctrl + Shift + F12**，会终止当前发送并持久暂停后续发送；核对微信状态后，双击根目录 `恢复微信发送.cmd` 恢复。结果不确定时先核对聊天记录，避免重复发送。

各工具的模块职责及代码合并记录见 [CODE_STRUCTURE.md](CODE_STRUCTURE.md)。

## 本地配置

- Python 依赖见根目录及各子项目的 `requirements.txt`。
- 微信：复制 `codex-wechat/wechat.codex.example.json` 为 `wechat.codex.json`，填写自己的账号与会话。
- FusionLive：复制 `FusionLive同步工具/app/local_credentials.example.py` 为同目录的 `local_credentials.py`，通过环境变量 `FUSIONLIVE_USERNAME`、`FUSIONLIVE_PASSWORD` 配置凭据。
- 上传工具：复制 `绿联云上传工具/config.example.json` 为 `config.json`，填写实际源目录、台账和目标路径。
- ima：在管理中心配置凭证、知识库和目录；设置保存于 `Ima知识库管理/runtime/settings.json`，加密凭证保存于同目录 `credentials.dat`，后者与 Windows 用户/机器绑定。
- 管理中心：需要固定网络配置时，复制 `管理中心/network_config.example.json` 为同目录 `network_config.json`，设置监听地址和端口。

账号密码、真实本地配置、数据库、会话记录、日志、业务文件、虚拟环境及发布压缩包均不纳入版本控制。克隆后需配置本机路径与账号。各组件的操作说明见对应目录。

## 目录与数据保留

| 位置 | 保存内容 | 清理建议 |
| --- | --- | --- |
| 根目录 `.venv-analysis/` | 所有工具共用的 Python 环境 | 删除后须重新安装，运行工具期间保留 |
| 根目录 `runtime/` | 测试报告、打包检查、排查证据和保留状态 | 按下节分类清理 |
| `FusionLive同步工具/runtime/` | 下载台账、恢复进度、分析缓存、调度与发送去重状态、推送设置 | 不要整目录删除 |
| `FusionLive同步工具/downloads/`、`history/` | 下载原件及历史版本 | 属于业务资料，按工具的版本管理流程处理 |
| `FusionLive同步工具/logs/` | 日志、每日日报、简报及发布记录 | 不要当作纯文本日志整目录删除 |
| `绿联云上传工具/runtime/` | 上传台账、续传及镜像归档状态 | 不要整目录删除 |
| `Ima知识库管理/runtime/`、`待同步/` | 配置、加密凭证、上传回执、每日次数、提取记录及资料副本 | 不要整目录删除；自定义资料目录也须保留 |
| `codex-wechat/data/` | 消息队列、去重、会话与问答记忆 | 不要作为缓存清空 |
| `管理中心/runtime/` | 操作任务、网页 Codex 对话、配置备份等 | 删除会丢失记录，不要整目录清空 |
| 各工具 `exports/`、`releases/` | 业务导出、安装及更新包 | 确认无保留需求后可清理旧文件；部分打包脚本另有输出位置 |

普通 `.log` 优先通过管理中心“运行日志 → 清除日志”清理；该入口跳过运行中的相关日志，并保留台账、配置、发送记录和简报。

### 根目录 runtime 可以删吗？

**可以分类清理；建议备份保留状态后再考虑整目录删除。根目录 `runtime/` 与各工具内部的同名目录用途不同。** 当前已核对的根目录内容如下：

- `test-reports/`：测试日志、JUnit 和耗时报告。不再需要追溯的旧报告可以删除，下次运行测试会重新建目录，但不会恢复旧报告。
- `package-checks/`、`logging-hash-probe-*/`：打包或日志检查留下的临时验证资料。确认相关检查已经结束且不再需要结果后可删除。
- `cleanup-reports/`：清理预览报告。不再需要审计时可删除。
- `retained-server-state/20261108-root-imports/`：此前从根目录移出的旧服务器状态，包含调度、注销、登录暂停及推送状态和迁移校验清单。属于保留证据，建议先备份；不要直接覆盖到正式工具状态目录。
- 根目录下的冲突排查 `*.json`、`query_fusion_*.py`、`simulate_server_conflict.py`、`build_shared_version_patch.py`：诊断资料与辅助脚本，确认排查结束且不再需要后可删除；重新运行脚本前需检查其实际操作。

按已核对的默认路径，正式业务台账使用各组件自身的 runtime，根目录 runtime 不是统一业务数据目录。备份需要保留的状态和证据、确认没有测试或打包任务正在使用后，可删除根目录 runtime；后续测试或清理工具可能重新创建它。若自行把配置路径指向这里，应先迁移对应数据。

`清理多余文件.cmd` 不是 runtime 清空工具：它仅对具备完整 `deployment-manifest.json` 的部署目录生成预览，默认不移动文件；显式加 `--apply` 并输入 `MOVE` 后才将候选旧代码移入待检查目录。runtime 等数据目录受保护。当前源码目录缺少部署清单时会拒绝清理。

## 维护、打包与迁移

| 工具或文档 | 作用 |
| --- | --- |
| `tools/run_tests.py`、`tools/test_suites.json` | 统一测试入口及功能分类映射 |
| `tools/cleanup_deployment.py` | 部署目录旧文件预览和隔离，对应根目录 `清理多余文件.cmd` |
| `tools/prepare_deployment.py` | 完整部署包解压后的内部路径修正和 ima 凭证导入；需要部署清单，不启动业务任务 |
| `tools/build_ima_update.py`、`tools/ima_update_apply.py` | 生成及应用 ima 专项更新包；具体覆盖范围和凭证选项应核对包内说明 |
| `管理中心/build_deployment.py`、`build_portable.py`、`build_update.py` | 生成项目部署包、便携包及更新包 |
| [部署与迁移说明](tools/deployment_guide.md) | 新目录部署、台账和业务资料迁移、凭证处理及配置保留 |
| [代码结构](CODE_STRUCTURE.md) | 各工具模块职责及公共逻辑位置 |

迁移时同时保留下载文件、对应台账、回执、发送去重记录及服务器配置。不要用旧诊断数据库覆盖正式数据库；加密 ima 凭证跨机器或 Windows 用户迁移需按部署说明重新配置。

## 测试

从项目根目录执行：

```powershell
# 默认 quick 基础检查，仅覆盖局部
& '.\.venv-analysis\Scripts\python.exe' tools/run_tests.py

# 按本轮实际改动选择功能；不确定时先查看计划
& '.\.venv-analysis\Scripts\python.exe' tools/run_tests.py --area file-counts --plan
& '.\.venv-analysis\Scripts\python.exe' tools/run_tests.py --area daily-text

# 完整回归
& '.\.venv-analysis\Scripts\python.exe' tools/run_tests.py --full
```

新开发环境另安装 `requirements-test.txt`。仅文档、发布清单或打包变化不重跑业务测试；仅相关前端改动才加 `--ui`。报告统一保存在根目录 `runtime/test-reports/`，分类、实际覆盖范围及更多命令见 [TESTING.md](TESTING.md)。
