# 服务器覆盖更新：2026.10.28-shared-codex-desktop.18

适用于已有阿联酋项目及共享 Python 3.12 环境的服务器。本包是程序覆盖更新，不是首次安装包；不含 Python 或虚拟环境。管理页面已构建，无需在服务器安装 Node.js 或重建前端。

包含管理中心、完整 codex-wechat 程序与技能、必要的 FusionLive 程序补丁和恢复发送入口。不包含实际服务器配置、账号凭据、微信数据库、聊天记录、模型摘要、IPC 认证材料、业务台账、下载资料、解析结果、日志或历史部署包。绿联云上传程序不变。

## 本次更新

- 微信与网页 Codex 共用本机后端代理。兼容的命令、目录权限与配置版本复用一个 App Server，事件按模型线程归属隔离，微信仍只读。网页保留持久会话，不增加主动预建轮换；微信继续按群/私聊复用及预建轮换。
- 共享后端最多同时生成2个任务，每个入口同时1个任务、最多64个已加载会话；连续空闲120秒或最后一个入口断开后释放进程。关闭一侧不强杀另一侧仍在使用的后端。网页归档释放后台订阅并保留历史。异常或超时不自动重放已经开始的生成。
- Codex 回复、推送文和简报图片共用跨进程桌面锁，从切换会话到恢复剪贴板逐条串行。文字和图片之间可穿插回复，但不会同时操作窗口或剪贴板。
- 发送时显示顶部提示并暂时拦截人工键鼠，35秒看门狗负责异常退出。其他不使用共享锁的微信自动化软件仍应停用。
- 保护期间按 **Ctrl + Shift + F12**，立即结束当前发送进程、恢复键鼠，并持久暂停后续发送。需要继续时双击项目根目录或同步工具目录的 **恢复微信发送.cmd**。暂停期间不消耗后续重试预算；任务有效期和定时窗口仍照常计算。
- 新任务使用持久化递增短编号；排队、开始提示与正式回复在“回复对象：@成员”一行执行原生 @，开头不重复 @。旧任务保留原编号及已冻结正文，避免破坏发送去重。
- 发送前核对目标会话并清空其中遗留草稿，包括人工输入的草稿。排队、开始和查询提示支持持久补发，默认最多尝试3次（含首次）、间隔至少5秒；阶段变化后跳过过时提示。结果不确定时核实历史，不盲目重发。
- 保留每日推送查看与手动推送、工具安全停止、一键启动/停止、操作记录和日志清理、项目问答及问答记忆等已有功能。

## 更新步骤

1. 安全停止微信监听、FusionLive 调度及后台解析、绿联云上传，等待任务收尾，再退出管理中心。关闭旧版发送进程后再覆盖，新旧发送器不可混用。备份原程序、配置和运行数据。
2. 将 ZIP 和同名 `.zip.sha256` 复制到服务器，解压到独立暂存目录，保持包内目录结构。先核对 ZIP 的 SHA-256。
3. 使用现有服务器 Python 运行暂存目录内的新校验脚本。以下假定项目位于 `D:\阿联酋项目`，ZIP 位于 `D:\更新`，当前 PowerShell 工作目录是暂存目录；按实际路径替换：

```powershell
D:\阿联酋项目\.venv-analysis\Scripts\python.exe .\管理中心\build_update.py --verify D:\更新\Project_Tools_Server_Update_2026.10.28-shared-codex-desktop.18.zip --target-root D:\阿联酋项目
```

应显示 `verified: true` 和 `base_installation_verified: true`。检查包括 ZIP CRC、逐文件哈希/大小、Python 3.12语法、同步工具版本及未随包提供的基础程序；不修改服务器文件、不登录平台、不调用模型、不操作微信。如果基础文件不匹配，停止覆盖并核对版本，不要用本机凭据覆盖服务器文件。

4. 验证通过后，将暂存目录中的 `管理中心`、`codex-wechat`、`FusionLive同步工具` 和根目录启动、安装及恢复发送脚本，按原层级**合并覆盖**至服务器项目根目录。不要先删除整个工具文件夹，也不要把暂存目录本身套在原项目外。
5. 完整保留 `.venv-analysis` 及所有工具的 `runtime`、`data`、`downloads`、`logs`、`exports`；保留 `codex-wechat/wechat.codex.json`、`管理中心/network_config.json`、`FusionLive同步工具/app/local_credentials.py`、上传配置、规则和范围配置。不要用示例文件替换已有配置。
6. 重启管理中心并强制刷新浏览器，再启动微信监听和其他工具。两套 Codex 入口及两套微信发送器都必须运行新版。共享后端注册目录由服务器自动创建，不要拷贝开发电脑的 `codex-wechat/data/shared-codex`。
7. 微信任务库自动补齐新增表/字段，问答、已确认发送记录和未开始的排队任务保留，中断生成不自动重放。网页历史会话仍保留，恢复时尝试使用原持久模型线程。

## 验收

- 在测试群连续提交两条问题，检查短编号、排队/开始提示和正式回复的 @ 位置、对象及北京时间。
- 发送时观察屏幕提示；测试紧急快捷键后，应恢复键鼠并暂停后续发送，再用恢复发送入口手动恢复。核对目标会话后，遗留或人工草稿会被清空。
- 同时使用网页和微信 Codex，对比网页 connected 事件的 `shared_backend.pid` 和微信 `generation-metrics.json` 的 `shared_backend_pid`，兼容配置应相同；关闭一侧后另一侧应能继续。网页不需要主动预建轮换。
- 在文件传输助手验证推送文和测试简报图片不与 Codex 争抢窗口；检查发送记录不重复。测试不会自动补发已错过窗口的业务日报。
- 核对原配置、业务台账、下载文件、问答历史和发送记录均保留。真实服务器的微信客户端、平台网络及模型可用性仍需部署后验证。

包在打包机验证前端构建、程序完整性、CRC/哈希、Python 3.12语法，以及本地模拟服务下的会话共享、隔离、并发上限、退出与回收。此前已在本机测试群/文件传输助手验证原生 @、草稿清理、补发、输入保护及快捷键；这些结果不等于服务器环境已经验收。
