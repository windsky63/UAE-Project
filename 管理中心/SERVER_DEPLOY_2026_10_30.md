## 更新内容

- 本次同步工具版本为 `2026.10.30-extraction-cache.1`。ZIP/7z 解压缓存独立于业务解析算法，按压缩包完整 SHA256 保存；同内容跨算法版本、修改时间或文件ID可复用，复用前校验解压文件的大小和SHA256。校验通过的旧任务解压文件可迁入缓存，支持嵌套包；缓存缺失、损坏或压缩包内容变化时重新解压。复用仍有读取和校验开销。
- 新版本成功提交解析结果后，自动清理同一平台文件已被替代的旧任务解压目录和解析中间文件，包含中断尝试遗留的目录。原始压缩包、台账版本记录和解析JSON报告保留；新版本未成功时保留旧版解压文件。共享缓存等当前队列全部成功完成后回收，仍被当前内容引用的文件保留。回退已清理的历史任务会重建解压路径。
- 可在安全停止后台解析后，从项目根目录单独清理旧版解压文件：`.\.venv-analysis\Scripts\python.exe .\FusionLive同步工具\main.py archive_cache --cleanup`。此操作会删除符合上述条件的派生文件，不删除下载原件；需要回看已清理的历史版本时可能重新解压。
- PCF特殊规则 `PCF-EXPORT-01`：识别编号时忽略 `-pcf.pcf` 中的 `-pcf` 导出标记，原文件名不变；识别依据标记此规则。`2-272-52-0001-AGX-WAB-pcf.pcf` 可识别为地上新建管道单线图、H2-272。仅补文件名兼容，不推断未确认的其他编号，也不将编号识别成功当作内容解析成功。
- codex-wechat 新增文件发送。模型根据当前用户自然语言及上下文确认发送意愿，不使用关键词或固定命令匹配；仅查找、询问能力、否定、未来计划、引用内容及意愿不清楚时不发送，必要时先确认。使用独立 `file_action` 字段、当前授权文件ID及当前用户授权原话；监听程序负责授权、版本、SHA256、目标聊天与持久去重。支持授权同步台账中的当前下载文件和已解压成员，单次一个文件，仅发到当前聊天；默认64MiB上限，`file_send_enabled=false` 可禁用，`file_send_max_mib` 可调整。文件发送保留草稿，不清空用户现有草稿。
- 文件发送复用跨工具桌面互斥、输入保护和紧急停止，已进入提交阶段但结果未确认时不自动重发。确认窗口需能核对文件名和接收会话，原生文件消息记录用于确认。已完成模拟模型、模拟微信与文件流程测试；尚未对服务器实际微信版本进行真实文件发送联调。
- `部署参考` 中附带两份编码规则原始PDF及 `PCF台账复核.xlsx`（2026-10-30 16:34台账快照）。复核表不是新服务器实时台账，不要覆盖服务器业务导出。1,979条PCF中，台账标记内容失败1条、内容冲突22条；按新编号规则仍有626条未识别。内容失败的具体原因仍需服务器原PCF或对应解析报告核实。

## 已有服务器的更新顺序

1. 将ZIP解压到独立暂存目录，先校验同目录 `.zip.sha256`，并使用包内 `deployment-manifest.json` 核对文件。不要直接向运行中的项目目录解压覆盖。
2. 安全停止下载调度、后台解析、NAS上传、定时推送、微信监听和管理中心，等待退出；不要强杀数据库写入进程。
3. 备份服务器现有程序、配置及业务数据，然后合并本包程序文件，保持四个目录同级。
4. **完整保留服务器 `runtime`、`downloads`、`history`、`logs`、`exports`、微信 `data` 和共享环境 `.venv-analysis`。** 包内不含开发机的这些业务数据。
5. **保留服务器上传 `config.json`、微信 `wechat.codex.json`、管理中心 `network_config.json`、同步 `app/local_credentials.py`，以及已有自定义计划、规则和模板。** 包内微信默认配置及同步登录文件仅供首次部署，更新时不要覆盖现有同名文件。自定义规则、模板与包内版本不同时，先核对差异；若属于同步完整性清单中的文件，应对确认保留的内容重新生成相应大小与摘要，不能跳过完整性检查。
6. 若已有正常的 Python 3.12 共享环境，继续使用；需要补依赖时在最终项目根目录执行 `.\.venv-analysis\Scripts\python.exe -X utf8 -m pip install -r requirements.txt`。需要新建环境时运行 `install_python312.cmd`；不要将不同Python版本的环境混合覆盖。本包没有夹带开发机Python 3.14环境。
7. 使用共享解释器运行以下离线检查，确认版本、摘要、依赖和原数据库可读取后，再按原方式启动管理中心及业务工具。

在项目根目录运行：

```powershell
& '.\.venv-analysis\Scripts\python.exe' '.\FusionLive同步工具\main.py' preflight --gui --wechat
& '.\.venv-analysis\Scripts\python.exe' '.\绿联云上传工具\main.py' integrity
Push-Location '.\codex-wechat'
& '..\.venv-analysis\Scripts\python.exe' -m wechat_local --check
Pop-Location
```

核对服务器原台账数量、上传进度和接收会话。上述检查不应替换成真实下载、上传或微信发送测试命令。

## NAS旧历史迁移是独立操作

程序更新不会自动整理所有旧NAS备份，也不修改本地历史文件名。

需要整理时，先安全退出上传调度，并确认没有其他程序修改同一NAS历史目录。在上传工具目录运行：

```powershell
& '..\.venv-analysis\Scripts\python.exe' main.py history-plan
# 检查 runtime/nas_history_plan.json 中的源路径、目标路径和冲突原因后，再执行：
& '..\.venv-analysis\Scripts\python.exe' main.py history-migrate
```

完整回读校验可能耗时。迁移会改变历史文件路径，引用旧路径的外部链接需更新；未知内容、歧义、链接目录和冲突目标保留原件。返回码2表示有未完成或冲突，部分无冲突文件可能已经迁移成功；结果见 `runtime/nas_history_result.json`。中断后可按迁移日志继续，不要删除原日志。

开发机只有Python 3.14环境：程序会校验Python 3.12语法，离线自动测试在开发机环境运行；服务器Python 3.12依赖安装、微信客户端及NAS权限仍需在服务器验证。

已知剩余问题仍保留：目标范围内本地缺失文件可能被上传完成状态忽略；存在但损坏的解析JSON缓存不会自动重建。本次打包没有将这两项说成已经修复。
