# ima 知识库管理

管理中心内的知识库管理页面与无界面命令行工具。默认使用本目录的 `待同步`，资料提取只复制副本，原文件与原压缩包保留。

## 操作导航

[项目说明](../../README.md) · [管理中心](../../管理中心/README.md)。命令行示例从本工具目录执行，统一回归命令从项目根目录执行。

日常顺序：配置并保存 → 提取本地副本 → 预览计划 → 核对目标与变更 → 执行计划。提取不改写下载原件；预览会联网读取云端，但不上传或移动文件；执行会产生实际云端变更。配置、文件或相关回执变化后需重新预览。

保留 runtime 内的凭证、设置、上传回执、每日次数和迁移记录，不通过清空目录处理限流或待核对状态。结果不确定先按下文“入库结果待人工核对”处理。配置变更后安全停止并重启常驻同步。

## 首次使用

1. 打开项目根目录的 `打开管理中心.cmd`，选择左侧“ima 知识库”。本目录的旧启动文件也会转到管理中心，不再打开 Tk 桌面窗口。
2. 在服务器安装项目根目录共享依赖；管理中心通过共享 `.venv-analysis` 启动无界面 ima 任务。
3. 凭证已配置时无需再次填写；需要更换时，在凭证区域填写 Client ID 和 API Key，点击“加密保存凭证”。可从 <https://ima.qq.com/agent-interface> 登录获取凭证，注意重新获取可能使旧 Key 失效。
4. 设置待同步、下载数据库和下载原目录，点击“读取知识库”选择目标并保存配置。在“云端内容”读取目录，必要时选择“设为同步目标”后保存。
5. 手动操作先点击“提取本地资料”；“自动同步前提取数据库资料”开关用于定时任务。原文件在服务器上时，请在服务器运行。
6. 点击“扫描本地文件”检查资料，再点击“预览上传计划”，结果显示在“最近上传计划”页签。预览不复制实际资料，也不上传云端。

计划将“待迁移”与“待上传”分别显示和筛选。已上传文件需要调整目录时，预览复用正式迁移的旧回执与路径映射，读取云端确认媒体身份，显示迁移前路径和新目标；不创建云端目录、不移动文件、不修改回执。相同内容先迁移后跳过上传；内容变化先迁移旧版再执行版本更新。旧回执对应媒体找不到时显示“已拦截”，不按新增上传；不同账号或知识库的回执不自动接管。更新前保存的旧计划需重新预览才能看到新状态。

知识库根目标下，已有明确本地迁移映射的预览直接按旧回执的云端父目录核对媒体，不先遍历旧、新两棵目录树；同一父目录的完整分页结果与媒体身份索引在本轮复用。待迁移文件不再额外读取新目录，正式执行时仍校验新目录、旧目录范围及同名冲突。日志分别输出本地扫描、迁移回执核对、云端分页和查重进度；大量目录和分页仍受接口节流约束，心跳不表示上传或迁移完成。

迁移、改名、建目录和入库成功后按接口回执更新目录快照，不重新读取列表。请求失败或响应丢失后清除相关缓存，重新预览并恢复。

无需改名、目标名称唯一的普通迁移按相同源目录和目标目录分组，每批最多 10 个媒体 ID，共用一次移动请求，并按成功回执更新两侧目录快照。服务端的 `MoveKnowledgeReq.Infos` 校验明确限制最多 10 项；旧版设置为 50，会在迁移组超过 10 项时返回错误 51。移动接口仍属于下文说明的未文档化接口。单文件尾批、改名和同名重复副本沿用原有处理流程。每个文件的迁移意图先持久化；批内任一结果缺失、失败或位置未确认时暂停，不进入新增上传。重新执行时先核对各媒体的实际位置，已移入目标的只补回执，剩余源媒体再按最多 10 项分批移动；不会直接重放整个失败批次。旧版超量请求被拒后已保存的迁移任务可继续使用，不需要清空 runtime 或 .ima-state；更新后重新预览再执行。安全停止在批次边界检查，当前请求可能已移动整批文件；保留迁移记录供续接。账号限频间隔保持不变，新文件仍分别申请媒体、上传对象和入库。
7. 核对目标后点击“执行预览计划”，确认弹窗后执行这份已保存的计划，不重新提取资料或全量生成计划。入库成功表示接口已接受，文档解析可能仍在进行。
8. “允许自动同步”默认开启以兼容旧配置；点击“启动自动同步”后，按北京时间每日定时执行，默认 13:00，可在同步配置中修改。自动同步一天最多一次，执行前持久记录次数，重启不重复执行；手动同步不受每日次数限制，也不占用自动同步次数；到点未运行时，启动后补执行当天一次。关闭网页不会终止后台任务。
9. 仅需手动同步时，关闭“允许自动同步”并点击“保存 ima 配置”。运行中的自动任务将在当前文件、批次或请求完成后安全退出；待状态显示“未启动”后按提取、预览、执行顺序操作。关闭状态持久保存在 `runtime/settings.json` 的 `auto_sync_enabled`，管理中心启动入口（含全部启动）和命令行 watch 均会拒绝自动同步。手动执行预览计划不占自动同步的每日次数；预览本身也不计次数。
10. 重新开启开关并保存不会直接启动任务，需点击“启动自动同步”。“安全停止”仅停止当前任务；其他配置变更仍需安全停止后重启才能应用。

手动同步和自动同步共用单实例锁及安全停止请求；关闭自动同步开关时仍可启动手动同步，点击安全停止会在当前文件或请求结束后退出。不会因为手动任务不属于自动监控而忽略停止请求。

手动预览生成唯一 `plan_id`，执行只读取 `runtime/preview-plan.json` 中的原文件清单。执行前在本地核对账号、源目录、目标、递归范围、提取配置、文件身份/大小/纳秒时间戳、上传回执和目录迁移记录；原文件或相关状态变化时要求重新预览，不偷偷生成替代计划。预览后新增的文件不纳入本次执行。上传前检查本地文件内容；查重结果与完整目录快照随计划保存，跨进程执行也复用，不逐文件重复联网查重。

新预览开始或正式提取时作废旧预览；失败的新预览不能退回执行上一份结果。执行开始后计划即被标记为已使用；成功、失败或安全停止后均需重新预览再执行，保留已有回执及迁移意图用于恢复。手动同步不受每日次数限制，但每次执行仍需有效的新预览；缺少预览、旧版计划或预执行校验失败均不能执行。迁移只处理本次计划包含的文件，迁移后只核对受影响的计划行，不再次扫描整个本地目录。自动定时任务仍按提取资料、生成当轮计划、执行的流程运行。

管理中心 ima 页面按用途分为四个入口：

- **同步工作区**：按“提取本地资料 → 预览上传计划 → 执行同步”操作，下方直接查看上传计划、本地文件和提取结果。自动同步的启动、停止位于工作区底部。
- **云端内容**：选择知识库、读取目录和搜索内容；“设为同步目标”会转到配置页，保存后才生效。
- **任务与记录**：分别查看后台任务、上传回执和每日记录，失败任务可直接打开对应日志。提交任务不代表执行成功；预览失败时明确提示下方可能保留上次结果。
- **同步配置**：集中设置目标、三个本地路径、提取开关、自动同步及凭证。未保存的修改会标记出来，并阻止按未保存配置发起提取、预览和同步。

上传计划、本地文件、提取结果、云端列表、后台任务、上传记录、每日记录均支持分页；可切换每页 20、50、100 条，并按关键词筛选，适用记录还支持状态筛选。计划通过本地记录接口读取完整结果，不再截断在前 500 项；上传回执不再限于最近 200 条。后台任务和每日记录同样可查询完整历史。日志弹窗按每页 20 条显示现有运行日志接口可用的输出。

仅“后台任务”页提供“清除已结束任务及日志”，包含当天已结束任务及其轮转日志，确认后立即刷新任务列表；清理不受筛选或分页影响。运行中任务保留；待核对任务只移除显示记录，日志保留；日志被其他运行中或待核对任务引用、路径不安全或删除失败时保留相应任务并报告原因。“上传记录”和“每日记录”不提供此按钮。上传回执是同步去重和恢复依据，不随任务及日志清理删除。

一次性预览和手动任务显示“任务处理中”，与常驻自动同步的“运行中”区分；外部锁占用显示“外部任务运行中”。旧锁文件存在本身不表示工具已启动；权限或 I/O 异常显示“运行状态无法确认”，不计入工作台运行工具数量，相关日志仍保留以免误删。

自动同步每轮记录资料提取、生成计划、执行同步等阶段。单个文件提取失败会输出具体原因并继续处理其他文件；一轮发生文件、接口或 SQLite 异常时，记录失败并等待次日定时执行，不在当天重新开启一轮；等待期间仍可安全停止。入库结果待核对的文件继续遵守回执保护，不会直接重复入库。手动单次任务仍通过非零退出码报告失败。

若日志末尾出现 `ima HTTP 403`，先看新版日志中的接口名称和业务错误原因。实际验证中，`check_repeated_names` 在连续逐文件请求时会返回 HTTP 403、业务码 `200001`、`请求频率超限，请稍后重试`；这种情况不能解释成凭证错误。预览优先复用本轮已经读取的完整目录列表查重；受管理资料目录直接读取一次完整列表，同时用于同名媒体识别和旧目录发现，不再额外调用重名接口。尚未读取目录列表的普通新增文件仍按每批最多 2000 项调用重名接口。未变化、待核对、已归档等文件继续使用原回执保护。每批返回必须完整且文件名唯一匹配，结果缺失或异常时仍停止，不跳过重名检查。执行复用预览查重结果，不再逐文件请求；预览后外部云端改动在下一次预览或接口错误后处理。

所有正式 OpenAPI 请求按账号共享节流状态（`runtime/api-rate.sqlite3`）：普通请求至少间隔 1 秒，同一账号的重名检查至少间隔 3 秒。这里是本工具采用的保守间隔，不是官方限额声明；预览仍按目录批量查重，上传前复用预览查重结果，不额外发起重名请求。

每次等待后都会重新检查共享冷却与请求间隔，只有当前可以发送时才领取名额，避免其他进程新增限流冷却后旧排队请求仍然发出。自定义 HTTP 会话和实验诊断入口也遵守同一个节流器；同一部署的 CLI、管理中心与定时任务不会各自独立放行。该状态只协调当前部署，不能控制其他机器或其他应用对同一账号的请求。

每收到一次明确的 `200001`、`110021` 或 HTTP 429 限流响应，本轮运行的普通请求和重名检查间隔都再增加 0.5 秒（例如 1/3 秒 → 1.5/3.5 秒 → 2/4 秒）。增量只保存在内存，本轮成功请求不会清零；程序重启、新客户端或常驻定时任务下一轮同步开始时，从基础 1/3 秒重新开始，旧版数据库中的自适应增量不再读取或更新。跨进程基础限频、已放行请求的短期时间间隔和服务端 Retry-After 冷却仍保留，重启不绕过有效冷却。普通权限拒绝、网络错误和额度码 220021 不触发加时。

接口收到明确的 `200001` 或 `110021` 限流响应时，最多尝试三次，重试前分别至少等待 30、60 秒；服务端的 `Retry-After` 更长时按其要求退避，冷却状态共享给其他进程。超过 5 分钟的冷却不阻塞当前任务，而是报告冷却并结束本轮。持续限流会中止本轮同步，不再逐文件继续请求；保留已成功回执及中止报告。`220021` 首次返回即中止，不等待或重试。普通权限拒绝不作为限流重试，写入请求遇到网络超时或无法确认结果的 HTTP 错误仍不自动重发。CLI 的节流和退避等待响应安全停止。错误保留接口名、业务码和经凭证脱敏的原因。

目录快照与批量查重结果随预览计划保存，执行阶段复用。成功写入更新快照，异常后清除相关缓存。目录路径与 ID 映射保存在 runtime/cloud-paths.sqlite3，按账号和本地源目录隔离；找到所选子目录后停止遍历。旧文件发现只扫描本轮涉及的资料分类。逻辑删除按同源同目标分组，每批最多 10 个文件，成功后立即保存归档回执。新文件仅申请媒体和提交入库，另有一次 COS 上传。

下次启动同步时，同一账号、知识库、目录、路径和内容指纹已有成功回执的文件跳过；普通失败文件重新尝试。已明确返回 `200001` 或 `220021` 的入库拒绝保留为可重试回执；网络中断等结果不确定的入库仍需人工核对，避免重复。这里是按文件恢复，不是从 PDF 文件的某个字节继续上传。自动同步仍限制一天最多一次，失败后不自动释放当天自动同步次数；手动同步可在重新预览后当天重试。请保留 `runtime/state.sqlite3` 和每日次数数据库，已有回执用于去重和恢复。

如接口返回的确为凭证或权限拒绝，再在服务器管理中心核对 ima Client ID / API Key，使用“读取知识库”核对可添加内容的知识库，选择目标并保存。若读取知识库成功而读取目标目录失败，还需核对目标知识库及文件夹标识和访问权限。修改配置或凭证后安全停止并重启自动同步。

## 从同步工具数据库直接提取项目管理规定、图纸与清单

默认只读同级 `FusionLive同步工具/runtime/ledger.sqlite3`，不读取、生成或刷新 Excel。每轮按数据库登记的文件身份、业务分类和路径映射，提取下载原目录中实际存在的资料，因此不受 XLSX 快照过期影响。“下载原目录”默认为 `FusionLive同步工具/downloads`；原文件在服务器上时，应在服务器运行。

管理中心“同步配置”中的“下载数据库路径”对应 `database_path`，可指定实际服务器数据库。旧配置没有该字段时，自动按已保存下载目录的同级 `runtime/ledger.sqlite3` 推导，读取配置时不擅自写回文件。手动点击“提取本地资料”或在自动同步配置中开启提取，无需先导出台账，本地提取也不需要 ima 凭证。

数据库以 SQLite `mode=ro` 和 `query_only` 打开，不创建、迁移或修改下载数据库。读取当前已提交快照后及时关闭连接；WAL 模式下不会把尚未提交的路径变化用于提取。文件身份由“工作区 + 内容ID”确定；按同一身份的 `local_paths.local_path`、`files.path` 和 `files.target_path` 查找实际文件。普通文件保留下载时的 `-2`、`-3` 等区分后缀，不按后缀大小选择所谓最新版。

以下载原目录中实际存在的文件为准，不要求其为平台最新版本或关联仍有效。新版尚未下载时，可提取仍留在下载原目录的旧版；新版尚无路径或文件尚未落盘时直接跳过，不记为提取错误。文件替换、移动及归档由同步工具管理，ima 不移动或修改下载原件，始终排除下载原目录外的 `history`、`runtime/download_ready` 等历史和暂存文件。筛选范围为全部专业 PP 正文、已确认分类的 PDF 图纸与设备、材料或碰口清单，不按同名文件猜选缺失身份。

业务分类复用同步工具已确认的编码规则，文件自身编号优先，不以目录名或标题猜测专业。包内资料只使用同步工具已提交、与本地父包版本匹配的成员索引，从 `runtime/file_analysis/jobs/.../extracted` 中复制已就绪文件。ima 不打开、读取或解压源 ZIP，也不递归读取嵌套 ZIP；ZIP 本身不提取、不上传。解压文件缺失或大小不匹配时等待同步工具重新解析，复制时校验已有 SHA256；不回退解压。父包在台账快照后发生变化时停止该条复制。旧 XLSX 只有包内路径、没有就绪文件索引时也不自行解压。

副本仍存放在 `待同步/项目管理规定/01～07 分类/文件名`，07 下不增加专业子目录。报告标明数据来源、工作区、内容 ID、实际来源和目标，界面以内容 ID 区分同名记录。读取快照后文件被移动或删除等提取异常会显示具体 ID 及登记路径；不改选其他身份的同名文件，不读取下载目录外的路径。上述本地文件筛选用于默认数据库模式；旧 XLSX 兼容入口仍按表内记录核验路径。

图纸副本按 `待同步/图纸/专业/业务类型/厂区/单元/文件名` 组织，与“项目管理规定”并列。只有单元属于 213、27、37、38、39、265、273，且专业属于钢结构、管道、安全、消防及火气设备的 PDF 图纸进入“图纸”；其余已识别图纸进入根目录“图纸（其他）”，层级完全相同。27 等单元匹配 027 等前导零编号，目录仍保留原编号。专业和单元以文件自身编号为准，不使用台账误填专业或原下载目录补猜。点击现有“提取本地资料”，以及同步前的自动提取，均应用此规则，无需新增配置。例如：


源内容变化且旧副本仍与该来源的提取回执匹配、且没有被其他来源复用时，校验旧副本后原子替换为新版，已分配的编号保持不变，不保存本地历史旧版。每次正式提取还会清理工具此前生成的 `待同步/删除/更新旧版` 专用目录；预览不清理，手动移入“删除”其他目录的文件保留。手工修改、没有匹配回执或被其他来源复用的不同内容保留原副本，新内容分配编号。缺失的正常副本仍可重新提取；源下载文件与源 ZIP 始终只读。NAS 上传与 ima 提取可同时只读打开原件；遇到 Windows 独占占用时，ima 等待 1 秒、2 秒重试读取，持续占用则记录失败并保留原副本，次日再试。复制期间源文件变化、被替换或移动时不发布该新版。

## 每日更新 TXT

待同步根目录维护一个 UTF-8 文件 `每日更新记录.txt`，由复制、上传和归档流程自动追加。每条一行，包含北京时间、操作、文件相对路径、结果，内容变化时附前后版本 SHA-256 的前 12 位；云端操作还包含知识库/目标目录，失败或冲突附简短原因。

示例：`2026-11-03 16:30:00 | 云端更新 | 项目管理规定/a.pdf | 成功 | 版本=旧摘要→新摘要 | 目标=知识库/根目录`。新增复制、本地副本更新、上传、云端更新、本地/云端逻辑删除及任务失败都会记录；未变化文件不逐条重复写，连续相同结果合并，恢复成功后再次失败仍保留，跨天重新记录。预览操作不写业务更新记录。

该 TXT 不参与上传，也不能通过本地逻辑删除按钮移走；隐藏的 `.ima-state/journal.sqlite3` 只用于合并连续重复记录。管理中心按记录分页显示历史，完整 TXT 同时保留在根目录。清理管理中心 `.log` 不会删除它。

大量提取结果按每批最多 128 条写入，复用数据库和 TXT 句柄，保留 SQLite FULL 持久化。每批先保存待写字节与文件偏移，再写入并刷盘；进程在写入前、部分写入或写完后中断，下次会先恢复，不丢记录、不重复追加。请保留 `.ima-state/journal.sqlite3`；已有文本被截断或待恢复位置被修改时报告错误，不覆盖人工内容。

性能优化同时包括：迁移路径和状态按索引查找；迁移哈希只在本轮文件身份、大小及纳秒时间戳均未变化时复用；正式复制直接暂存到目标同目录后原子发布，避免第二次临时文件复制。提取报告的 `timings_seconds` 和日志记录读取状态、迁移、读取台账、复制校验、回执保存、每日记录等阶段耗时。

管理中心提取、预览、同步及自动任务使用 `--summary`，日志仅输出结果摘要和报告位置，完整明细仍由页面读取。独立 CLI 默认保留完整 JSON 输出，也可显式加 `--summary`。本轮没有缩短 API 限频间隔或放宽文件、回执校验。

## 文件同步规则

- 默认源目录为 `Ima知识库管理/待同步`，也可手动选择其他目录。这里没有自动选用已整理的 1.8 GB ZIP 或全部项目文档。
- 勾选“包含子目录”会递归扫描，按本地相对路径建立云端目录树。各级目录与本地采用相同规则，不同目录中的同名文件分别处理。
- 支持 PDF、Word、PPT、Excel、CSV、Markdown、TXT、PNG/JPEG/WebP、XMind、HTML、EPUB。按官方大小限制预检，图片额外校验真实文件签名。此版本未启用音频上传，因为还需要可靠校验两小时的时长限制。
- ZIP、视频、未知类型、空文件、超限文件会显示“已拦截”。扫描忽略隐藏文件、Office 临时文件和链接目录，不读取源目录外的链接目标。
- 已成功上传且内容 SHA-256 未变化的本地文件按账号、知识库、文件夹和本地路径分别记录，后续自动跳过。
- 云端对应目录有唯一同名普通文件、本地没有匹配上传回执时，预览显示“云端已存在”；正式同步假设它就是当前本地文件，补建包含云端媒体 ID 和当前本地 SHA-256 的成功回执，不重复上传。此时以本地内容为基线，不下载核验云端内容。多个同名条目、同名文件夹或无法确认媒体 ID 时仍报告冲突。
- 同路径、同名文件内容改变时，若云端有唯一匹配本工具旧版上传或认领回执的同名条目，会自动更新并归档旧版。自动同步不做永久删除或权限修改。
- 直接从磁盘删除文件不会影响云端；需要逻辑删除时，将文件移入同步目录内的“删除”子目录。成功记录是本机上传回执，不是云端实时镜像；若用户在云端删除过资料，本机仍可能显示“已同步”。
- 多个本机上传任务通过 SQLite 进程锁互斥，防止 GUI 与命令行同时上传。来自其他电脑/客户端的并发同名写入仍由服务端行为决定，无法保证原子去重。
- 正式写入不做盲目自动重试。若最终入库请求超时、响应缺失，或进程在入库中途退出，会保留“待人工核对”状态，避免重复入库。

## 云端操作范围

自动同步按待同步内的文件生成任务，不把云端目录当作需要全量清理的镜像。云端手工创建而本地没有对应项的目录、文件保持原状。例如，本地 `项目管理规定` 只有 `01` 到 `07`，云端额外的 `08` 不会被遍历或作为写入目标；云端额外的 `项目.csv` 不会被移动、改名或替换。

实验管理按钮也执行相同限制：源文件必须同时有本地同名文件和同账号、知识库的媒体 ID 回执（包含正式同步补建的认领回执）；目标目录必须对应本地目录；创建云端目录前，本地必须已经存在对应目录。单独在云端改名成一个本地不存在的新名称同样被拒绝。缺少回执时，先预览并执行同步以认领云端对应目录中的同名文件。

执行前会重新检查本地文件及云端旧版名称，防止预览后文件已被移除或改名仍继续修改。工具自身为更新和归档维护的 `更新暂存`、`删除/更新旧版` 目录仍用于存放有明确本地来源和回执的版本，不对其中其他用户文件进行清理。

## 同名文件的更新过程

例如今天上传 `a.pdf`，明天同步工具在原路径下载了内容不同的新 `a.pdf`：

1. 数据库提取校验本地旧副本后，直接将正常位置的副本原子替换为新版，不再保留本地 `待同步/删除/更新旧版/...`。原下载文件只读。
2. 上传计划显示“待更新”。只有同一账号、同一云端目标、同一本地路径的旧上传回执与当前唯一云端同名条目匹配时才会自动替换。
3. 新版先上传到当前云端同步目标的 `更新暂存/任务目录`，核验该条目存在。这个核验不代表服务端已完成文档解析。
4. 确认新版入库后，将旧版移入云端 `删除/更新旧版/版本目录`，保留原文件名。再把新版移到正常目录，正常目录最终只保留新版。
5. 新版上传失败时，旧版仍留在正常目录。若旧版归档或新版发布阶段中断，会保存更新任务并在下次同步继续核对，旧版文件仍保存在删除目录中，不会被永久删除。
6. 更新成功后，重复同步跳过未变化的新版。旧版可由用户在 ima 中手动清理。不同文件名或不同本地路径的文件仍按独立文件处理，不凭相似文件名猜测版本关系。

这些更新状态与上传回执保存在 `runtime/state.sqlite3`。新版暂存入库结果不明确时，先按媒体 ID 重新读取目录；仍无法确认则显示“待人工核对”，可用已有“处理待核对”入口处理，不会盲目重传。

## 本地“删除”目录的逻辑删除

默认位置为 `Ima知识库管理/待同步/删除`。将文件从正常同步位置**移动**至这里，就作为逻辑删除；也可在工具的“本地文件与同步计划”页选中文件，点击“移入删除目录”。选择其他同步源目录时，工具同样建立其 `删除` 子目录。

例如原文件 `待同步/资料/a.pdf` 应移至 `待同步/删除/资料/a.pdf`，保留相对路径。这个目录中的文件不会作为新增文件上传，即使开启递归或自动同步也一样。

预览和执行规则：

- 仅移入本地删除目录时，界面显示“本地已逻辑删除”，文件内容仍保留在磁盘。
- 若同一账号和同步目标有原路径、相同 SHA-256 内容的成功上传回执，计划显示“待逻辑删除”。执行同步时，会把该媒体 ID 对应的云端文件移入**当前云端同步目标目录下**的 `删除` 子目录，必要时创建该目录。
- 移动后核验源目录中不再存在该媒体 ID，且删除目录中存在，才显示“已逻辑删除”。最终清理由用户在 ima 客户端处理。这个功能使用此前实测的未文档化移动/建目录接口，不调用永久删除接口。
- 找不到匹配的成功上传回执时，仅保留本地逻辑删除状态，不根据文件名猜测云端对象。复制进删除目录但原位置仍保留文件时会拦截。文件内容变更后与回执不一致也不会自动移动云端旧文件。
- 本地删除目录已有同路径文件时拒绝覆盖。云端删除目录内已有同名文件时，在删除目录下创建按媒体身份区分的子目录，保留旧归档和原文件名。
- 移动响应中断时保留目标位置，下次同步先检查是否已移入，避免重复操作。重新同步已逻辑删除文件不会再次上传或移动。
- 将文件移回本地原位置不会自动恢复云端文件；云端恢复需在 ima 中手动完成。已手工移动到其他云端目录的文件，也需要先核对位置再处理。

## 凭证与本机数据

凭证通过 Windows DPAPI 加密，保存在 `runtime/credentials.dat`，只能由当前 Windows 用户在可解密的环境中使用。不要将该文件作为可移植配置分发。普通设置中不保存 API Key。

用户明确要求携带凭证的私有部署包可通过 `build_deployment.py --overlay --include-ima-credentials` 生成。包内 `credentials.bootstrap.json` 含可迁移明文凭证；服务器首次读取时加密到该服务器用户的 `runtime/credentials.dat` 并删除迁移文件。已有加密凭证优先保留，成功读取后也删除迁移文件；环境变量配置优先级最高。请私下传输和保存含凭证的 ZIP，解压目录中的自动删除不会移除 ZIP 内的原始内容。

也可使用环境变量，优先于本机加密文件：

```powershell
$env:IMA_OPENAPI_CLIENTID = '你的 Client ID'
$env:IMA_OPENAPI_APIKEY = '你的 API Key'
```

两个值必须一起设置。兼容 `IMA_CLIENT_ID` / `IMA_API_KEY` 变量名。接口凭证仅发给 `ima.qq.com`；COS 上传仅使用服务端临时凭证，禁止跟随上传重定向。日志与回执不保存凭证或 COS 签名。

`runtime/settings.json` 保存源目录和选定目标；`runtime/state.sqlite3` 保存上传回执；`runtime/preview-plan.json` 保存不可变的可执行预览，`runtime/preview-state.json` 单独保存使用状态，避免每次状态变化重写完整清单；`runtime/latest-plan.json` 保存最近预览或执行结果。它们包含本地路径等私人元数据，已忽略 Git 提交。`待同步` 内的实验资料同样被忽略。

## 命令行

从本工具目录运行，下例 `python` 可替换为 `..\..\.venv-analysis\Scripts\python.exe`：

```powershell
python -m ima_manager configure
python -m ima_manager scan
python -m ima_manager bases
python -m ima_manager list --kb '列表返回的真实ID'
python -m ima_manager search --kb '列表返回的真实ID' '关键词'
python -m ima_manager plan --kb '列表返回的真实ID'
python -m ima_manager sync --kb '列表返回的真实ID'            # 只预览
python -m ima_manager sync --kb '列表返回的真实ID' --execute  # 执行上一次成功预览，不能省略预览
python -m ima_manager watch --kb '列表返回的真实ID' --execute --interval 60
python -m ima_manager status
```

GUI 保存的源目录和目标会作为命令行默认值；显式传 `--source`、`--kb`、`--folder` 可覆盖。`--folder ''` 表示根目录，`--top-only` 表示只扫描源目录顶层。ID 必须来自服务端响应，不能从网页地址猜测。

不确定记录也可在人工核对后解锁：

```powershell
python -m ima_manager resolve --kb '真实ID' --path '本地文件绝对路径' --outcome uploaded --execute
# 确认未入库才使用 --outcome absent
```

`watch` 持续运行时，Ctrl+C 请求停止；不需要模型或 Agent 消耗。

### 2026-11-04：按相对目录同步

预览和执行均按本地相对目录逐层匹配所选云端目录。例如，所选目标为知识库根目录时，`待同步/项目管理规定/02_质量管理/a.pdf` 对应云端 `项目管理规定/02_质量管理/a.pdf`。若所选目标已是云端“项目管理规定”，则以对应本地子树为基准，不再重复创建一层“项目管理规定”；其他本地子树会标记为不在当前目标范围。

预览显示云端目标路径并读取对应目录中的文件，不创建目录或上传。缺少的目录仅在执行同步时创建；路径存在重名文件夹或文件占用时停止该文件的同步。不同目录可有同名文件。旧版平铺计划必须重新生成。

“云端已存在”表示同一目标路径已有唯一同名普通文件。正式同步会重新核对本地内容及云端媒体 ID，然后假设它就是本地文件并补建成功回执；预览不写回执。后续以认领时的本地 SHA-256 为基线检测内容变化，再执行原有版本更新及旧版归档。上传前才出现的唯一云端同名文件也按此规则认领；同名条目不唯一、身份变化或无法确认时报告冲突。已有待核对入库状态仍须先处理，不会用认领绕过。更新、逻辑删除和人工核对均使用文件实际所在的云端父目录。

### 2026-11-11：缺失回执时识别旧云端目录

当前目标路径没有文件、正常回执迁移也未匹配时，预览会补查所选云端目标中的旧资料目录。仅对本地受管理资料根目录（项目管理规定、图纸、图纸（其他）、设备材料清单相关目录、其他图纸）内的文件进行同名匹配；知识库根目录下只进入这些资料目录或与本地源目录同名的包装目录，不扫描其他无关目录。跳过隐藏目录、删除及更新暂存目录。所选云端目标自身的平铺文件也参与匹配。

本地同名文件唯一、扫描范围内云端同名普通文件也唯一时，显示“待迁移”，记录预览中的原目录和媒体 ID。正式执行重新核对本地内容与源媒体身份，持久保存认领回执及迁移任务后，使用原有批量迁移流程移动文件；迁移成功后补齐正确目标回执，不重新上传。缺失回执时按用户要求假设云端内容就是当前本地内容，不下载验证；之后的本地内容变化正常走版本更新和旧版归档。预览期间不建目录、不写回执、不移动云端文件。

本地或云端同名文件不唯一时显示冲突，不将这些对象当作新增上传；已有未完成更新或待核对状态仍须先处理。正确路径已有文件时保持“云端已存在”，不额外移动旧目录中的同名副本。仅执行选中的计划文件。迁移请求已生效但响应丢失时，下次根据已保存的媒体 ID 和任务核对恢复，避免重新上传。

旧目录核对按目录读取完整列表，同一次预览使用目录缓存，不逐文件重复读取；大目录的分页请求仍由现有接口处理。进度日志输出已读取目录和剩余目录数量。存在尚未匹配的资料时需要完整核对扫描范围，以发现重复同名对象；所有资料已匹配回执后跳过该补充扫描。

云端旧空目录：已实测 move_knowledge 对文件夹返回 220001“不支持文件夹”，delete_folder 返回 HTTP 404。程序不会假报目录已归档，也不反复尝试不支持的接口。迁移后在 runtime/empty-folder-cleanup.json 保存旧源目录候选：empty 为本轮快照已知为空，needs_check 为未额外联网确认；当前计划仍使用或快照中有内容的目录不列入。清单不增加云端请求，实际清理需在 ima 客户端完成。

中断迁移后重新预览，先按已记录的旧父目录确认媒体仍在原处；确认存在就不读取该文件对应的新目标目录。仅当旧目录找不到媒体时，才读取迁移目标确认是否已经移动。多个文件共用一次旧目录分页及媒体索引，避免为大量尚未移动的文件读取刚创建的空目标目录。此优化不改变正式移动的身份与结果核验，也不缩短账号限频间隔。

服务器清空 ima 的 `runtime` 后，重新配置账号凭证、源目录、知识库及同步目标，再重新预览并执行同步，即可从云端对应目录中的同名文件重建回执。清空 `runtime` 也会删除 `credentials.dat`、`settings.json`、预览及未完成任务记录；云端已有内容与当前本地内容的对应关系以重新认领时的假设为准。
